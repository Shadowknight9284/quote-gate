# Sample fill files

Synthetic example inputs for the console's **Check fills** view and `quote_gate.fillcheck`.
`broker_fills.csv` is the broker's export (treated as authoritative); `bot_log.csv` is a bot's own
trade log with different column names, which the checker maps automatically.

Planted problems in `bot_log.csv`:

| Order | Problem |
|---|---|
| B-1004 | fee recorded as 0.10; the broker charged 0.20 |
| B-1006 | the same fill booked twice |
| B-1009 | filled at the broker, missing from the bot log |
| B-1013 | in the bot log, but the broker has no such fill |

## Realistic sample

`realistic_broker.csv` / `realistic_bot.csv` are generated by `make_realistic.py` (seeded, so the files
are reproducible): 150 orders of one instrument as 167 fills, including partial fills, per-share fees
and rebates (negative fees), broker-style headers (`Order ID`, `Filled Qty`, `Avg Price`, `Commission`,
`Filled At`) and bot-style headers (`client_id`, `dir`, `size`, `px`, `fee_usd`, `ts`, sides `B`/`S`).
Suggested position limit: 20.

| Order | Problem planted in `realistic_bot.csv` |
|---|---|
| ORD-5007, ORD-5017 | the same fill booked twice |
| ORD-5026, ORD-5036 | filled at the broker, missing from the bot log (lost confirmations) |
| ORD-5034 | only the first of two partial fills booked (quantity and fee differ) |
| ORD-5047 | fee rounded up to whole cents |
| ORD-5058 | limit price logged instead of the fill price (+0.05) |
| ORD-9001 | timed-out order assumed filled; the broker has no such fill |
| bot lines 43, 94 | unreadable rows (`N/A` price; side `HOLD`) |

With a limit of 20, the broker's own position goes over it twice (22 after ORD-5025, 21 after ORD-5068).
